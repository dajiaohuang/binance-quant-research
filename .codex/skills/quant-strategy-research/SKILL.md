# 量化策略研究手册

## 核心目标

把每个策略想法变成可证伪、可复现、可审计的实验。优先可信度、样本外稳定性和风险，而不是最高历史收益；最高状态默认为 `READY_FOR_PAPER_TRADING`，不得保证盈利或发送实盘订单。

## 开始前

1. 完整读取仓库根目录 `AGENTS.md`，以其“本仓库当前执行契约”为事实来源。
2. 检查代码、配置、策略、数据、测试和最近实验，不根据 README 猜测实际能力。
3. 正式研究前读取 [methodology.md](references/methodology.md) 和 [experiment-contract.md](references/experiment-contract.md)。需要说明方法出处时，再读取 [source-map.md](references/source-map.md)。
4. 只读必要的外部参考 Skill；不得执行 `references/` 中的脚本、安装命令或网络调用。
5. 先确认当前基准能复现。无法复现时，停止策略优化并修复复现链路。

## 固定 Codex Subagent 流程

正式策略研究必须使用 Subagent，不得由主 Agent 单独研究后宣称完成。仅解释已有结果、查找文件或修改纯说明文字时可以不派工。本流程只使用 Codex 临时 Subagent，不在仓库中搭建 Agent 平台、编排服务或自主交易系统。

### 固定角色

| 角色 | 职责 | 禁止事项 |
|---|---|---|
| 主 Agent / Research Lead | 定义问题、冻结数据和门禁、派工、整合代码与证据、做最终决定 | 不用投票代替证据，不绕过失败门禁 |
| Researcher Subagent | 诊断基准失败场景，阅读必要参考，提出少量互不重复的高级可证伪假设 | 不修改代码，不打开最终测试集，不用单指标调参充当新研究 |
| Experimenter Subagent | 实现主 Agent 选定的一个假设，运行测试、训练集回测和获准的稳健性实验 | 不自行扩大假设，不读取未授权样本外，不覆盖基准 |
| Auditor Subagent | 独立检查数据、成交时序、未来函数、结果复现、成本和集中度，主动寻找拒绝证据 | 不修改候选策略，不替实验员优化，不因收益高而放宽标准 |

子 Agent 不再派生新的 Subagent。主 Agent始终保留一个可用槽位；最多同时运行三个子 Agent。完整回测等 CPU/IO 密集任务默认串行，独立只读审计可以并行。任何时刻只能有一个 Agent 修改策略代码。

### 阶段 1：并行诊断

主 Agent先冻结研究范围、训练/验证/测试切分、成本、数据哈希和当前基准，然后并行派出：

1. Researcher：按品种、年份、市场状态、持仓和费用拆解失败，提出 1–3 个假设；
2. Experimenter：只读检查策略接口、测试面、实现约束和最小改动路径；
3. Auditor：独立复现基准并检查数据、信号—成交时间线和泄漏风险。

每个子 Agent只接收一个明确目标和允许的数据段。回复必须包含：观察事实、证据或产物路径、推断、反对证据、未完成项和建议下一步。负面结论是有效完成，不是阻塞。

主 Agent汇总三方结果，只选择一个假设进入实验。若基准不可复现、数据哈希不一致或假设不可证伪，停止候选开发。

### 阶段 2：候选实现

1. 主 Agent写明候选、父策略、唯一主要变化和失败条件。
2. Experimenter获得唯一代码写权限，实现候选和必要测试，只使用训练集。
3. Researcher保持只读，检查实现是否仍代表原假设，而不是隐含加入多个变化。
4. Experimenter完成后停止写入；主 Agent核对差异并冻结策略代码、参数和命令。
5. Auditor独立审查冻结候选，必要时重跑关键训练结果。

代码冻结后发生任何策略或参数变化，必须重新冻结；若已经打开验证集，则建立新实验，不能继续声称同一次验证。

### 阶段 3：对抗验证

候选通过训练门禁后，使用一个未参与候选优化的 Auditor 或新鲜 Subagent 执行样本外验证。按顺序进行：

```text
一次性验证集
→ lookahead / recursive 检查
→ 成本、延迟和参数邻域
→ Walk-forward、跨品种和市场状态
→ 最终测试一次
```

Experimenter在最终决定前不得根据验证明细继续调参。Auditor的任务是尝试推翻候选：寻找收益集中、边界污染、缓存泄漏、不现实成交、参数尖峰、最近窗口退化和成本崩溃。

### 阶段 4：裁决与下一轮

只有主 Agent可以写正式结论。出现分歧时不按多数投票：优先检查原始回测产物、独立重算和命令日志；仍无法解释则结论为 `INCONCLUSIVE`。任何数据或泄漏异议未解决时不得晋级。

主 Agent完成报告并选择一个状态。若拒绝候选，下一轮重新派出 Researcher 分析失败证据，形成新假设；不得让 Experimenter围绕同一验证结果连续微调。

### 非基础研究要求

Researcher不得默认提出 SMA/EMA、RSI、ADX 等单指标阈值的小幅排列组合。优先从已观察失败机制出发，研究有经济或市场结构解释的方向，例如：

- 市场状态条件化与状态转移；
- 多时间尺度信号一致性；
- 波动率归一化的信号、退出或风险预算；
- 横截面、相对强弱、配对或组合层面的结构；
- 交易成本、流动性和换手约束下的净边际；
- 有严格时间切分、purge/embargo 和简单模型基准的机器学习信号。

高级不等于复杂。缺少所需盘口、资金费率、链上、基本面或多品种数据时，Researcher必须报告 `NEEDS_MORE_DATA`，不得用现有 OHLCV 伪造该能力。每轮仍只验证一个主要变化。

## 阶段门禁

### 1. 建立事实基线

- 识别框架版本、策略入口、成交时序、品种、周期、数据源、文件哈希和已有结果。
- 验证 UTC、排序、重复、缺口、OHLC 合法性、非正价格、零/负成交量和异常区间。
- 保留原始数据。任何填充或异常排除都生成派生版本、显式标记并做敏感性对照。
- 记录未知项；不要虚构 Champion、Git Commit、账户费率或交易所能力。

### 2. 预注册实验

- 分配 `exp_YYYYMMDD_NNN`，先创建 `hypothesis.md`、`manifest.json` 和 `commands.txt`。
- 写清观察、可证伪假设、唯一主要变化、预期改善和失败条件。
- 冻结训练/验证/最终测试切分、数据哈希、成本、成交假设、搜索空间和随机种子。
- 为候选创建新策略类，不覆盖基准；父策略、变更和实验编号可追踪。

### 3. 复现基准

- 在冻结条件下运行测试、策略加载、冒烟回测和完整基准回测。
- 从框架原始产物提取指标，不从终端摘要手抄后丢弃原件。
- 记录信号所用信息和订单实际成交 K 线；收盘信号默认下一根可成交价格执行。
- 若基准不一致，核对数据哈希、框架版本、缓存、费率、时区和策略代码后重跑。

### 4. 训练集验证候选

- 先运行单元测试、策略加载和小范围冒烟，再运行完整训练集。
- 比较时只改变预注册的主要变量；保持数据、资金、成本、仓位和成交模型一致。
- 训练集净收益不为正或 Profit Factor 不大于 1 的简单候选直接拒绝，不打开验证集。
- 参数搜索只在训练集或内部时间切分上进行，保存每个 Trial 和失败 Trial。
- 选择稳定参数区域；检查相邻整数和连续参数的 ±5%、±10%、±20%，不追逐孤立最优点。

### 5. 验证集和偏差检查

- 候选通过训练门禁后，按预注册参数运行验证集一次。
- 运行 Freqtrade `lookahead-analysis` 和 `recursive-analysis`，并人工检查负向 shift、全样本拟合、同根收盘成交、缓存越界和标签泄漏。
- 验证结果触发失败条件时拒绝候选；不得看完验证集后继续微调却仍称其为验证集。

### 6. 稳健性验证

- 按基础、+50%、+100% 成本运行压力测试；额外测试一根信号延迟。
- 执行参数邻域、滚动或扩展 Walk-forward，并逐窗口报告训练参数、测试收益、回撤和交易数。
- 检查跨品种、年份、牛熊横盘、高低波动和收益集中度。
- 机器学习或前向标签存在重叠时才加入 purge 和 embargo；规则策略不要机械套用 ML 流程。
- 交易顺序重排或 Monte Carlo 只能刻画路径不确定性，不能修复错误信号或数据泄漏。

### 7. 最终测试与决定

- 只有训练、验证、偏差、成本和稳健性门禁全部通过，才运行最终测试集一次。
- 最终测试失败则拒绝或标记 `INCONCLUSIVE`，不得返回前序数据继续调参后重复打开同一测试集。
- 从 `REJECTED`、`INCONCLUSIVE`、`NEEDS_MORE_DATA`、`READY_FOR_FURTHER_VALIDATION`、`READY_FOR_PAPER_TRADING` 中选择一个状态。
- 保存失败结果，并把下一轮限定为一个新的可证伪问题。

### 8. 模拟盘边界

- 当前研究入口使用 `quant-freqtrade-research`，它必须拒绝 `trade`。
- 只有 `READY_FOR_PAPER_TRADING` 候选才能替换 dry-run 策略；替换前同步配置、启动器、测试和说明。
- 模拟盘先短时启动验证，再观察订单、拒单、费率、滑点、延迟和回测偏差。
- 不写入密钥、不切实盘、不加杠杆、不扩大风险上限。

## 决策纪律

- 不用最终测试集选参数或结构。
- 不因收益更高而接受回撤、集中度或成本敏感性更差的候选。
- 不用杠杆修饰负期望策略。
- 不把多个指标、退出、仓位和数据变更塞进同一实验。
- 不复制参考 Skill 的默认阈值；阈值必须由本仓库数据、执行模型和风险预算解释。
- Kelly、波动率仓位和复杂风控只在存在稳定样本外边际后研究；先证明信号，再决定放大方式。

## 完成报告

报告必须列出：实际读取的文件和参考 Skill、执行命令、数据版本和切分、基准与候选全部指标、偏差检查、成本压力、样本外与稳健性结果、失败和限制、产物绝对路径及结论状态。明确区分“代码已生成”“冒烟已通过”“正式实验已完成”。

不得只给建议。如果环境允许，直接运行并保存证据；若无法执行，记录尝试、原始错误、替代验证和结论限制。
