reproduced offline before the fix: after a valid fake-transport run, adding the
canonical top-level field `"alpha":{"fabricated":true}` to
`corpus_summary.json` still let `load_corpus()` return `unit /
NEEDS_MORE_DATA`; the reproduction exited zero. The previous frozen source SHA
`717731da62e2c5e4c910706c3d2bbacc633e300d11cd21409492518e5cb9c0b4`
and its command binding are therefore superseded and must not be executed.

The minimal evidence-contract fix adds three inseparable checks:

- `corpus_summary.json` bytes must equal the exact canonical pretty-JSON
  encoding generated by the extractor;
- its top-level key set must equal the extractor's generated summary field set,
  which is also disclosed by the schema;
- trusted JSON parsing rejects duplicate object keys before Python can collapse
  them. This applies to the root summary and other trusted JSON/JSONL evidence.

Focused regressions prove rejection of the canonical fabricated `alpha` field,
noncanonical root-summary bytes, and a duplicate top-level `run_id`. The
generator also asserts its own top-level field set before writing. This closes
tampering required by the existing frozen evidence contract; it does not alter
acquisition policy, corpus semantics, endpoints, timing, retries or eligibility
boundaries. V3 remains untouched.

## Implemented single change

Only the v3 acquisition timing and retry evidence was replaced. V3 corpus
semantics remain intact and the v4 module imports no v3 runtime helper.

- Retryable statuses are exactly 408, 429, 500, 502, 503 and 504, and only a
  fully recomputed `HTTP_<status>` outcome is eligible for retry.
- Attempt numbers are absolute 1 through 4. HTTP 429 uses 30/60/120-second
  delays; other retryable statuses use 1/2 seconds and terminate at attempt 3.
- Any case-insensitive `Retry-After` presence on a retryable response is
  terminal, including empty, zero or malformed values. Redirects, malformed
  evidence, header drift, nonretryable status and transport exceptions are
  terminal.
- Accepted OK responses sleep exactly one second before the next logical
  request. There is no sleep before the first wire or after accepted
  `time_after`.
- The lease starts a process-local monotonic 10,800-second wall budget. The
  timeout is capped at 30 seconds without upward rounding, and the absolute
  acquisition-wide wire cap is 3,464.
- Each successful transport response commits body, sidecar, then an immutable
  receipt. Receipts form a single global SHA-256 chain and each `NEXT_WIRE`
  receipt records and authorizes its exact validated sleep and next scope.
- Controlled response-less/orphan failure modes write a separate, write-once
  `terminal_schedule.json`; its presence forbids success.
- A successful raw summary binds the runtime contract, request ledger, receipt
  head/tree, sorted raw artifact tree, exact keysets and counts. It excludes
  itself, processed output and root artifacts from the promised raw-tree hash.
- Success requires exact selected-detail/accepted-detail equality and exact
  ledger-attempt/body/sidecar/receipt bijections, with no terminal schedule,
  orphan, pending response or extra raw artifact.
- The trusted loader recomputes every outcome, absolute retry decision, delay,
  sleep authorization, chain, tree, byte/hash binding, request sequence,
  semantic corpus output and success bijection from frozen evidence.
- Extractor SHA is checked before lease, around runtime creation, sleeps, each
  wire, raw commit, raw summary and final artifacts. Source drift fails closed.

The CLI exposes only the two timing tuples
`--http-429-backoff-seconds 30 60 120` and
`--other-retryable-backoff-seconds 1 2`; the old timeout, attempt-count,
wire-cap and pacing flags do not exist. All remaining timing policy is
hardcoded.
